# ПОЛІТИКА КОНФІДЕНЦІЙНОСТІ ПРОЄКТУ

## «Планувальник справ»

**Версія:** 1.0  
**Дата:** 02 жовтня 2026 р.

## 1. Призначення документа

Ця політика визначає, які дані обробляє локальний застосунок «Планувальник справ», де вони зберігаються, для чого використовуються та які обмеження встановлюються щодо їх поширення.

## 2. Скоуп політики

**У межах політики:**
- дані, які користувач вводить у форму задачі;
- дані, які записуються у `tasks.json`;
- локальна обробка задач для сортування, фільтрації, визначення прострочення та формування нагадувань;
- локальні резервні копії даних, якщо така функція буде додана.

**Поза межами політики:**
- дані інших користувачів, оскільки багатокористувацький режим не планується;
- серверна або хмарна обробка;
- передавання даних через мережу;
- сторонні аналітичні та рекламні сервіси;
- облікові записи, профілі та онлайн-синхронізація.

## 3. Модель використання

«Планувальник справ» є **однокористувацьким локальним застосунком**. Користувач працює зі своїм переліком задач на одному пристрої. Для роботи застосунку не потрібні реєстрація, авторизація, сервер або підключення до мережі.

## 4. Які дані обробляються

Поточна реалізація створює та зберігає такі дані задачі:

| Поле | Призначення |
| --- | --- |
| `id` | Унікальна ідентифікація задачі у локальному списку. |
| `title` | Назва задачі, введена користувачем. |
| `deadline` | Дата та час виконання задачі. |
| `priority` | Пріоритет: високий, середній або низький. |
| `remind_minutes` | Інтервал нагадування перед дедлайном або відсутність нагадування. |
| `reminded` | Ознака, чи було нагадування вже показано. |
| `done` | Ознака виконання задачі. |

Фактична структура випливає з поточного програмного коду та не передбачає окремого поля для імені, електронної пошти, пароля чи ідентифікатора облікового запису.

## 5. Мета обробки

Дані використовуються виключно для функцій самого планувальника:
- створення та відображення задач;
- редагування і видалення задач;
- зміни статусу виконання;
- сортування за дедлайном або пріоритетом;
- приховування виконаних задач;
- визначення прострочених задач;
- показу локальних нагадувань.

## 6. Місце та спосіб зберігання

Дані зберігаються у локальному файлі `tasks.json`, розташованому поруч із файлом програми. Поточна реалізація читає JSON при запуску та записує його після зміни задач.

Дані не передаються на віддалений сервер програмною логікою поточної версії. Перенесення файлу на інший пристрій, копіювання у хмарне сховище або передавання іншій особі виконується вже на рівні операційної системи чи дій користувача та не є штатною мережевою функцією застосунку.

## 7. Доступ до даних

Основний доступ має користувач пристрою, який запускає застосунок. Застосунок не передбачає механізму розмежування доступу між кількома користувачами.

Тому конфіденційність у поточній архітектурі значною мірою залежить від захисту самого облікового запису операційної системи та файлової системи пристрою.

## 8. Заборонені дані

Не рекомендується використовувати планувальник для зберігання:
- паролів і секретних ключів;
- токенів доступу;
- банківських реквізитів;
- іншої високочутливої інформації, яка не потрібна для виконання задачі.

За необхідності запису чутливої інформації користувач повинен розуміти, що поточна версія зберігає `tasks.json` у звичайному локальному JSON-форматі та не виконує шифрування цього файлу.

## 9. Видалення та зберігання

При видаленні задачі запис видаляється з поточного списку та зберігається оновлений `tasks.json`. Окремого механізму безпечного стирання залишків даних із диска поточна версія не реалізує.

Якщо в майбутньому буде додане резервне копіювання, термін зберігання копій та правила їхнього видалення повинні бути окремо визначені.

## 10. Майбутні зміни

Додавання хмарної синхронізації, експорту на сторонні сервіси, спільного доступу або багатокористувацького режиму змінює скоуп цієї політики. Перед реалізацією таких можливостей потрібно окремо визначити нові категорії даних, точки передавання та правила доступу.
