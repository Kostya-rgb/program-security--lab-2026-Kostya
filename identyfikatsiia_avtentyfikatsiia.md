# ІДЕНТИФІКАЦІЯ ТА АВТЕНТИФІКАЦІЯ

## «Планувальник справ»

**Версія:** 1.0  
**Дата:** 19 жовтня 2026 р.  
**Пов’язано:** FR-13..FR-19, NFR-08, BL-13..BL-17, UC-07..UC-10, AT-13..AT-21, T-01, T-10..T-12.

## 1. Підсумок рішень

| Питання | Рішення |
| --- | --- |
| Єдиний спосіб ідентифікації | Вибір імені користувача зі списку профілів на пристрої. |
| Автентифікація | Пароль — **необов’язковий**, задається окремо для кожного профілю. |
| Зберігання | `users.json`; пароль лише як хеш scrypt із випадковою сіллю. |
| Сеанс | Лише в пам’яті процесу; без токенів, файлів сеансу й автовходу. |
| Завершення сеансу | «Вийти», закриття вікна, автовихід через 15 хв неактивності (лише профілі з паролем). |

## 2. Ідентифікація

| Ідентифікатор | Тип | Призначення |
| --- | --- | --- |
| `username` | рядок, 3–32 символи: літери, цифри, `_` `-` `.` | Ім’я для вибору при вході; унікальне без урахування регістру. |
| `id` | випадковий hex (16 символів) | Внутрішній ключ; не змінюється й не використовується повторно. Зберігається в `owner` кожної задачі. |

Сценарії:

1. **Перший запуск** — користувачів немає, показується створення профілю. Задачі з попередньої версії (без `owner`) призначаються першому створеному профілю.
2. **Подальші запуски** — вибір імені зі списку.
3. **Новий профіль** — з екрана входу, ім’я + необов’язковий пароль.
4. Кожен профіль бачить і змінює лише задачі з власним `owner`.

Електронна пошта, телефон, справжнє ім’я не збираються.

## 3. Методи автентифікації

| Метод | Статус | Сценарій |
| --- | --- | --- |
| M-1. Вибір імені | Обов’язковий | Завжди; для профілю без пароля є єдиним кроком входу. |
| M-2. Пароль (8–128 символів) | Опційний | Задається при створенні профілю або пізніше («Пароль…»); якщо задано — вимагається при кожному вході. Можна змінити або прибрати (потрібен поточний пароль). |

Не підтримуються: OTP, біометрія, SSO/OAuth, відновлення забутого пароля (поза скоупом).

## 4. Зберігання автентифікаційних даних

`users.json` (поруч із програмою):

| Поле | Опис |
| --- | --- |
| `id`, `username`, `created` | Ідентифікація. |
| `password` | `null` або `{alg: "scrypt", n, r, p, salt, hash}`; n=2¹⁴, r=8, p=1, сіль 16 байт, ключ 32 байти. |
| `failed`, `locked_until` | Лічильник невдалих спроб і час завершення блокування (epoch). |

Правила: пароль у відкритому вигляді не зберігається й не журналюється; запис атомарний (тимчасовий файл + заміна), права `0600` там, де ОС це підтримує; при пошкодженому `users.json` програма **не запускається** (fail-closed) і файл не перезаписується автоматично.

## 5. Порядок входу

1. Користувач вибирає ім’я зі списку.
2. Пароль не задано → сеанс створюється одразу.
3. Пароль задано → перевірка блокування → scrypt із збереженими параметрами і сіллю → порівняння через `hmac.compare_digest`.
4. Невдача: `failed += 1`; після 5 спроб — блокування на 60 с (зберігається між запусками), лічильник скидається. Повідомлення без технічних деталей.
5. Успіх: лічильники скидаються, створюється сеанс.

## 6. Сеанс і завершення

- Сеанс = `{id, username}` у пам’яті `TodoApp`; на диск не записується, при кожному запуску потрібен новий вхід.
- Доступ до задач — лише через вибірку за `owner` поточного сеансу.
- Завершення: кнопка «Вийти» або закриття вікна — повернення на екран входу, дані сеансу очищуються, нагадування зупиняються; автовихід після 15 хв без дій для профілів із паролем (константа `IDLE_SECONDS`).

## 7. Обмеження

- Профіль без пароля не захищає від особи, яка має доступ до застосунку.
- Розмежування задач логічне, не криптографічне: `tasks.json` і `users.json` не шифруються та доступні всім, хто має доступ до файлів ОС (див. T-02, T-05, T-10).
- Нагадування працюють лише під час активного сеансу.
- Забутий пароль не відновлюється.
