# МОДЕЛЬ РОЗПОВСЮДЖЕННЯ ТА ЛІЦЕНЗУВАННЯ

## «Планувальник справ»

**Версія:** 1.0  
**Дата:** 24 жовтня 2026 р.  
**Реалізація:** `licensing.py`, `updater.py`, `integrity.py`, `version.py`, `issue_license.py`, `sign_release.py`

## 1. Обрана модель

**Freemium + безстрокова ліцензія (Perpetual license) для редакції Pro.** Базова редакція Free безкоштовна; Pro відкривається одноразовою ліцензією без обмеження в часі (на всю мажорну версію 1.x).

| Модель | Рішення | Причина |
| --- | --- | --- |
| Subscription, SaaS | Відхилено | Потрібні сервер і облікові записи; вони поза скоупом проєкту (локальний офлайн-застосунок) |
| Trialware, Shareware, Demoware | Відхилено | Офлайн не можна надійно відлічувати час: локальний лічильник обходиться перевстановленням |
| Crippleware | Відхилено | Безпека (шифрування, контроль доступу, перевірка цілісності) не може бути платною опцією |
| Freeware | Частково (Free) | Лишає користувачеві робочий продукт без обмеження в часі |
| **Freemium + Perpetual** | **Обрано** | Не потребує сервера; ліцензія перевіряється офлайн; користувач не втрачає дані |

## 2. Умови використання

| Параметр | Free | Pro |
| --- | --- | --- |
| Ціна, строк | Безкоштовно, безстроково | Одноразова ліцензія, безстроково, оновлення 1.x |
| Профілі на пристрої | до 3 | без обмежень |
| Задач на профіль | до 30 | без обмежень |
| Безпека (шифрування, доступ, цілісність) | **усі функції** | усі функції |
| Пристроїв | будь-яка кількість окремих встановлень | **1** (прив'язка до коду пристрою) |
| Обліковий запис, телеметрія | не потрібні, немає | не потрібні, немає |
| Активація | не потрібна | офлайн: код пристрою → файл ліцензії |
| Перенесення на інший пристрій | — | повторна видача ліцензії видавцем |

Правила: при втраті ліцензії або зниженні до Free наявні задачі лишаються доступними для читання, зміни й видалення; блокується лише створення нових понад ліміт. Ліцензія 1.x не діє на 2.x.

## 3. Механізм контролю

**Ліцензія** (`license.lic`): `{"payload": {product, edition, serial, licensee, device, major, issued}, "sig"}`. Підпис Ed25519 над канонічним JSON. Підробка чи зміна будь-якого поля ламає підпис.

**Код пристрою:** SHA-256 від ідентифікатора машини (`machine-id` / `MachineGuid` / `IOPlatformUUID`), 24 hex у групах по 4. Сам ідентифікатор нікуди не передається.

**Активація (офлайн, виклик-відповідь):** користувач бере код пристрою («Ліцензія…» або `--device-id`) → видавець виконує `issue_license.py issue` → користувач активує файл («Ліцензія…» або `--activate`). Файл копіюється в `license.lic` лише після успішної перевірки.

| Перевірка | Де | Коли | Реакція на невдачу |
| --- | --- | --- | --- |
| Підпис, продукт, пристрій, версія в ліцензії | Локально (відкритий ключ) | Запуск, активація, **перед кожним gated-запитом** (створення профілю, задачі) | Редакція Free + повідомлення; дані не блокуються |
| Ліміти профілів і задач | Локально, у `AuthService.register` і `TaskService.create` | Перед операцією | Відмова операції з поясненням |
| Видача ліцензій, облік серійних номерів, відкликання, підрахунок пристроїв | **Сторона видавця / сервер** (поза застосунком) | Під час продажу | — |

Офлайн-застосунок не може підрахувати пристрої чи відкликати ліцензію: це зроблено через прив'язку до одного пристрою; відкликання й облік можливі лише на стороні видавця (підписаний список відкликань у майбутньому оновленні).

## 4. Ключі

| Ключ | Де зберігається | Призначення |
| --- | --- | --- |
| Приватний ключ **ліцензій** | Лише у видавця, `~/.planuvalnyk/license_private.pem` (0600), не в проєкті | Підпис ліцензій |
| Відкритий ключ ліцензій `license_public.key` | У проєкті, входить до підписаного маніфесту | Перевірка ліцензій |
| Приватний ключ **випуску** | Лише у видавця, `~/.planuvalnyk/release_private.pem` | Підпис маніфесту й пакетів оновлення |
| Відкритий ключ випуску `release_public.key` | У проєкті; відбиток записано у звіті | Перевірка коду та оновлень |

Ключі ліцензій і випуску окремі: компрометація одного не дає підробляти інше.

## 5. Що потребує перевірки автентичності та захисту від підміни

| Компонент | Механізм | Коли |
| --- | --- | --- |
| Файли програми (`main.py`, `access_control.py`, `crypto_store.py`, `integrity.py`, `licensing.py`, `updater.py`, `version.py`, `requirements.txt`, `license_public.key`) | Маніфест SHA-256 + підпис Ed25519 | Запуск, `--verify` |
| Файл ліцензії | Підпис Ed25519 + прив'язка до пристрою | Див. п. 3 |
| **Пакет оновлення** | Маніфест підписано **встановленим** `release_public.key` (не ключем із пакета); хеші всіх файлів; точний склад; імена без шляхів; ліміти розмірів; версія лише вперед | `--update`, до запису будь-чого на диск |
| Встановлення оновлення | Резервна копія, атомарна заміна файлів, підсумкова `verify_release`, автовідкат при збої | Під час оновлення |
| Залежність `cryptography` | `pip install --require-hashes` (організаційно, у коді не реалізовано) | Встановлення |

Порядок випуску оновлення: змінити код і `version.py` → `python sign_release.py package` → передати `planuvalnyk-<версія>.update.zip` користувачам (канал може бути ненадійним: підміна виявиться) → користувач: `python main.py --update <файл>`.

## 6. Обмеження

- Код на Python відкритий: хто змінює файли, може вимкнути перевірки ліцензії (це виявляє підпис випуску лише за умови його перевірки з довіреним відбитком). Модель ліцензування спирається на підпис ліцензії, прив'язку до пристрою й договірні умови, а не на DRM.
- Зміна «ідентифікатора машини» (перевстановлення ОС) потребує повторної видачі ліцензії.
- Ключ випуску не ротується оновленням (пакет із `release_public.key` відхиляється); заміна ключа — ручне перевстановлення.
- Відкликання ліцензій і онлайн-активація не реалізовані (поза скоупом: сервера немає).
